# Transaction Field Specification

## Overview

This document provides comprehensive specifications for transaction data fields expected by the ComplianceGuard system for upload, processing, and compliance evaluation.

---

## Transaction Data Model

### Core Fields

| Field Name | Type | Required | Max Length | Description | Validation Rules | Example |
|------------|------|----------|------------|-------------|------------------|---------|
| `transaction_id` | String | Yes | 50 | Unique transaction identifier | Must be unique, alphanumeric with hyphens | `TXN-2024-001234` |
| `entity_id` | String | Yes | 100 | Entity/organization identifier | Alphanumeric, no special chars except hyphen/underscore | `ACME-CORP-001` |
| `type` | String | Yes | 50 | Transaction type | Must be one of: WIRE_TRANSFER, ACH, CARD, CHECK, CASH, CRYPTO | `WIRE_TRANSFER` |
| `amount` | Decimal | Yes | 19,4 | Transaction amount | Must be > 0, max 15 digits before decimal | `95000.00` |
| `currency` | String | Yes | 3 | ISO 4217 currency code | Must be valid 3-letter code | `USD` |
| `from_account` | String | No | 50 | Source account number | Alphanumeric | `ACC-12345` |
| `to_account` | String | No | 50 | Destination account number | Alphanumeric | `ACC-67890` |
| `from_country` | String | No | 2 | ISO 3166-1 alpha-2 origin country | Must be valid 2-letter code | `US` |
| `to_country` | String | No | 2 | ISO 3166-1 alpha-2 destination country | Must be valid 2-letter code | `CH` |
| `customer_id` | String | No | 50 | Customer identifier | Alphanumeric | `CUST-5678` |
| `timestamp` | ISO 8601 | No | - | Transaction timestamp | Valid ISO 8601 format | `2024-05-03T10:30:00Z` |
| `description` | String | No | 500 | Transaction description | Free text | `International wire transfer for services` |

### System-Generated Fields (Auto-populated)

| Field Name | Type | Description | Generated By |
|------------|------|-------------|--------------|
| `status` | String | Processing status: PENDING, APPROVED, FLAGGED, REJECTED | Rule Engine |
| `risk_level` | String | Risk assessment: LOW, MEDIUM, HIGH, CRITICAL | Rule Engine |
| `risk_score` | Decimal | Numerical risk score (0.00-1.00) | Rule Engine |
| `flagged_rules` | String | Comma-separated list of violated rule IDs | Rule Engine |
| `created_at` | Timestamp | Record creation timestamp | System |
| `updated_at` | Timestamp | Last update timestamp | System |
| `reviewed_by` | Long | User ID of reviewer | Manual Review |
| `reviewed_at` | Timestamp | Review timestamp | Manual Review |

### Supported Transaction Types

| Type | Code | Description | Typical Use Case |

## Compliance Rules & Thresholds

| Rule ID | Description | Threshold | Risk Weight |
|---------|-------------|-----------|-------------|
| `AML-001` | Large transaction threshold | Amount > $10,000 | 0.35 |
| `AML-002` | High-risk country origin | from_country in FATF list | 0.45 |

| Rule ID | Description | Condition | Risk Weight |
|---------|-------------|-----------|-------------|
| `KYC-001` | Missing customer ID | customer_id is null/empty | 0.30 |

| Rule ID | Description | Threshold | Risk Weight |
|---------|-------------|-----------|-------------|
| `BASEL-001` | Large exposure limit | Amount > $1,000,000 | 0.25 |
| `BASEL-002` | Capital adequacy breach | Cumulative exposure exceeds limit | 0.40 |

## CSV File Format

### Standard CSV Template

```csv
transaction_id,entity_id,type,amount,currency,from_account,to_account,from_country,to_country,customer_id,timestamp,description
TXN-001,ACME-CORP,WIRE_TRANSFER,95000.00,USD,ACC-12345,ACC-67890,US,CH,CUST-5678,2024-05-03T10:30:00Z,International wire transfer
TXN-002,BETA-INC,ACH,5000.00,USD,ACC-11111,ACC-22222,US,US,CUST-1234,2024-05-03T11:00:00Z,Domestic ACH payment
TXN-003,GAMMA-LLC,CARD,250.00,EUR,CARD-9999,MERCH-8888,DE,FR,CUST-9999,2024-05-03T11:30:00Z,Card payment
```

### CSV Requirements

- **Header Row:** Required (first row must contain field names)
- **Delimiter:** Comma (`,`)
- **Encoding:** UTF-8
- **Line Endings:** LF (`\n`) or CRLF (`\r\n`)
- **Quotes:** Optional for text fields, required if field contains comma
- **Date Format:** ISO 8601 (`YYYY-MM-DDTHH:mm:ssZ`)

## Excel File Format

### Supported Formats

- `.xlsx` (Excel 2007+)
- `.xls` (Excel 97-2003)

### Excel Requirements

- **Sheet:** First sheet is processed
- **Header Row:** Row 1 must contain field names
- **Data Rows:** Start from row 2
- **Column Order:** Must match CSV specification
- **Cell Formats:**
  - Text: String fields
  - Number: Amount field (decimal)
  - Date: Timestamp field (ISO 8601 or Excel date)

## Validation Rules

### Field-Level Validation

```java
// Transaction ID
- Required: true
- Pattern: ^[A-Z0-9-]+$
- Max Length: 50
- Unique: true

// Entity ID
- Required: true
- Pattern: ^[A-Z0-9_-]+$
- Max Length: 100

// Amount
- Required: true
- Min Value: 0.01
- Max Value: 999999999999999.9999
- Decimal Places: 4

// Currency
- Required: true
- Pattern: ^[A-Z]{3}$
- Valid Codes: ISO 4217 list

// Country Codes
- Pattern: ^[A-Z]{2}$
- Valid Codes: ISO 3166-1 alpha-2 list
```

### Business Rule Validation

```java
// Cross-field validation
if (type == "WIRE_TRANSFER") {
    require(from_country != null)
    require(to_country != null)
}

if (amount > 10000) {
    require(customer_id != null)
}

// Duplicate detection
if (exists(transaction_id)) {
    reject("Duplicate transaction ID")
}
```

## Error Codes & Messages

### Validation Errors

| Code | Message | Resolution |
|------|---------|------------|
| `VAL-001` | Transaction ID is required | Provide unique transaction ID |
| `VAL-002` | Invalid amount format | Use decimal format (e.g., 1000.00) |
| `VAL-003` | Invalid currency code | Use 3-letter ISO code (e.g., USD) |
| `VAL-004` | Invalid country code | Use 2-letter ISO code (e.g., US) |
| `VAL-005` | Duplicate transaction ID | Use unique transaction ID |
| `VAL-006` | Amount must be greater than zero | Provide positive amount |
| `VAL-007` | Invalid transaction type | Use supported type (WIRE_TRANSFER, ACH, etc.) |

### Processing Errors

| Code | Message | Resolution |
|------|---------|------------|
| `PROC-001` | Failed to parse file | Check file format and encoding |
| `PROC-002` | Database connection error | Retry upload |
| `PROC-003` | Rule engine evaluation failed | Contact support |
| `PROC-004` | Batch size exceeds limit | Split into smaller batches (<10,000 records) |

## Integration Points

### API Endpoints

```
POST /api/transactions/upload
- Accepts: multipart/form-data
- Parameters: file (CSV/Excel), fileName
- Returns: BatchIngestionResult

GET /api/metrics/batch/{batchId}
- Returns: BatchMetricsDTO with processing status

GET /api/transactions?status=FLAGGED
- Returns: Paginated list of flagged transactions

GET /api/metrics
- Returns: Dashboard metrics (real-time)
```

### Event Flow

```
1. File Upload → TransactionController
2. Parse & Validate → FileParser + ValidationService
3. Batch Persist → TransactionRepository
4. Fire Events → ComplianceScanService (CDI)
5. Process Rules → ScanAgent → RuleEngine
6. Update Status → TransactionRepository
7. Record Metrics → MetricsService
8. Display Dashboard → MetricsController → Frontend
```

- **Max File Size:** 10 MB
- **Max Records per Batch:** 10,000
- **Max Processing Time:** 5 minutes

### Processing Throughput

- **Parse Rate:** ~1,000 records/second
- **Validation Rate:** ~2,000 records/second
- **Persistence Rate:** ~500 records/second (batched)
- **Rule Evaluation:** ~100 records/second (async)

- **File Upload:** < 2 seconds
- **Batch Validation:** < 5 seconds (1,000 records)
- **Initial Response:** < 3 seconds

## Troubleshooting Guide

### Common Issues

**Issue:** Upload fails with "Invalid file format"
- **Solution:** Ensure file is CSV or Excel (.xlsx/.xls)
- **Check:** File encoding is UTF-8

**Issue:** Validation errors for all records
- **Solution:** Verify CSV header row matches specification
- **Check:** Column order and field names

**Issue:** Transactions stuck in PENDING status
- **Solution:** Check rule engine processing logs
- **Check:** Verify CDI event bus is running

**Issue:** Dashboard metrics not updating
- **Solution:** Refresh browser, check API connectivity
- **Check:** Verify MetricsService is recording scans
